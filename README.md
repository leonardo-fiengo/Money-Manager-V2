# Money Manager

Run the local app with `.venv\Scripts\python.exe run.py`, then open http://127.0.0.1:5000. The launcher processes due payments at startup and every minute. Page, API, health and asset requests do not process scheduled payments. A separate scheduler can call `flask --app app process-scheduled` when using a different server.

Build the Windows app with `powershell -File build_executable.ps1`. The executable is `dist\MoneyManager.exe`; its data lives beside it in `dist\data`. Source runs use the root `data` directory. Close an older running version before launching an update.

Money is stored in integer cents. On the first updated launch, an atomic migration preserves record IDs and relationships and converts legacy amounts using decimal rounding. Generated major-unit columns retain compatibility with existing read queries. A local SQLite snapshot is saved before the migration, once each day the app runs, and before every restore.

Settings & tools → Backup & restore exports all records and merchant logos. Both JSON exports and downloaded ZIP snapshots can be uploaded, validated and reviewed before replacing records. Restore first saves the current database and logos. Local snapshots are in `data\backups`; keep an exported copy on another device for protection against disk loss. The installation's session key in `data\.secret-key` is private and is intentionally excluded from exports.

Foreign-currency transactions retain the conversion rate, source and rate date used when saved. If live rates are unavailable, the app labels the conversion as estimated. Editing a description or category keeps that original conversion. Charts are bundled locally and work without a CDN connection.

`static\css\money-manager.css` is the active stylesheet; older stylesheet files are retained as references. Interface assets use modification timestamps for cache invalidation.

Run regression checks with `.venv\Scripts\python.exe -m unittest discover -s tests`. Tests use temporary databases. Browser verification should also use a copied database rather than creating review transactions in personal records.

Settings & tools now links to transaction rules, merchant aliases, import history and bank profiles, transfer matching, reconciliation history, transaction recovery, and daily net worth history. Sidebar destinations have no back arrow; secondary screens return to the page you opened them from, with a safe parent-page fallback.

CSV importing accepts UTF-8, Windows-1252, and BOM-marked UTF-16; detects delimiters and decimal conventions; and suggests English or Italian date/description columns. Map and review ambiguous dates before confirming. Save a named profile to automatically reuse the mapping for the same account and column headings. Rules have priorities, combined conditions, bounded regular expressions, actions, and a preview of up to 5,000 existing records. The first enabled matching rule suggests changes in the import preview. Correcting a merchant learns its original statement description as an alias.

Import fingerprints use the original bank values, so rule renaming does not defeat duplicate detection. Duplicate rows remain unchecked unless explicitly overridden. Completed batches with unchanged records can be rolled back; changed tags, splits, receipts, settlements, linked payments, or reconciliation locks require review first. Removed records are retained under Transaction recovery, including receipts and pending card settlements.

Match imported outgoing/incoming pairs only after reviewing that they are a movement between your own accounts. Matching keeps balances intact and excludes the pair from income and expenses; unmatching restores the original records. Refunds, reimbursements, and chargebacks link to an original expense and reduce reported spending. Credit card settlements retain explicit links to purchases.

Balance checks accept a statement through date. Matched or adjusted sessions close and lock financial fields of their transactions; multiple overlapping sessions retain their own membership. Reopen every relevant session before changing a checked record or an account opening balance. Reopening retains recorded adjustments. Difference previews identify similarly sized entries and possible duplicates with correction links.

The forecast simulates 30/60/90/180/365 days using posted balances, pending payments, recurring income and expenses, future card settlements, and a 90-day discretionary spending average. Saved scenarios model monthly income, spending, and investment changes without writing transactions. Per-account projections show scheduled activity; the total chart also includes average spending and scenario changes. Foreign recurring payments retain their original currency and a saved EUR estimate; generated payments save the rate used when created.

Subscriptions suggests recent payments with regular weekly/monthly/yearly intervals and similar amounts, shows annual and monthly cost, price changes, and the next expected date, and lets you track a reviewed pattern as a recurring rule. Recurring rules have occurrence history; removed generated payments are not generated again. Savings goals support target dates and estimated completion from recent contributions. Transaction details support notes and PDF/image/text receipts up to 5 MB. Accounts can be archived and reactivated while retaining their history. Settings also chooses dashboard panels; Ctrl+K and B remain available for navigation and privacy.

Snapshots carry a schema version and include receipts and merchant logos. SQLite integrity and foreign-key checks run after migrations; a separate snapshot is saved before upgrading an existing database. SQLite uses WAL, a writer timeout, and atomic financial operations. Transaction listing uses FTS5 search and server pagination.

Click an account from Accounts or Overview to see its balance, recent activity (including incoming transfers), monthly spending, category breakdown, and balance history. Account checks can open directly for that account. Missing card numbers and expiry dates are not fabricated.

Savings pots reserve existing money across one or more active bank, cash, prepaid card, or wallet accounts. Enter each source amount under "Where from?"; the total must match the contribution. Reservations leave balances unchanged. Releasing money reduces the selected source reservations. Existing pots without sources must have their reserved money attributed before further contributions or spending. Completed pots offer "Spend them already": tick the checkbox and record spending to create one EUR expense per source account, release the reservations, and mark the pot spent. Spending is atomic and cannot run twice. It records purchases in the app; it does not send payments. Delete releases an active pot's reservations without changing balances, preserves any recorded expenses, and allows restoration when enough money remains available. Backup schema 12 includes source allocations, movement sources, spent/deleted state, and spending references; older backups still restore with unattributed pots.

Backup & restore can enable encrypted automatic snapshots with a passphrase of at least 12 characters. New files use the .mmbackup extension; existing ZIPs and JSON exports remain plain. Encryption uses authenticated Fernet with an Argon2id-derived key; see https://cryptography.io/en/latest/fernet/. Only a locally wrapped derived key is retained in data/.backup-encryption.json, tied to data/.secret-key. Keep the passphrase to restore on another installation or after changing it. Encrypted files can be uploaded with the passphrase and reviewed before restore. Session and encryption configuration files are excluded from exports and source control.
